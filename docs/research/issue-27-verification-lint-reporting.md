# Deterministic lint diagnostics in gate verification

Hosted run `37420040421` rejected the planted `@opencode/plugin` runtime import
correctly, but verification shards 11/16 and 12/16 rejected that result. Oxlint's
GitHub formatter emits the rule name and primary diagnostic, not the configured
help (`OpenCode plugin imports must be types only.`). The verifier requires every
expected substring, so this was a reporting mismatch, not a missing restriction.

## Public regression seam

Starting from integration `fd7dda3`, this public, externally bounded command
reproduced the exact failure locally:

```sh
env -u OPENCODE -u AI_AGENT GITHUB_ACTIONS=true CI=true \
  VERIFICATION_SHARD=11/16 bun run verify-gates
```

The failure was `OpenCode plugin runtime import forbidden (ts): wrong result
(exit 1)`. Its output contained `title=eslint(no-restricted-imports)` and
`'@opencode/plugin' import is restricted from being used.`, but no `types only`.
Removing the two agent variables matters: Oxlint's automatic agent formatter
otherwise takes precedence over its automatic GitHub formatter and hides the
hosted regression.

## Smallest fix and caller audit

The verifier now passes Oxlint's native `--format=default` for lint commands only.
No parser, formatter dependency, production lint configuration, public lint script,
exit-status assertion, or other gate's output changes. Ordinary GitHub source lint
still produces annotations. SDK rejection now requires the complete rule name,
SDK package, exact configured help and fixture extension, rather than two partial
substrings. Both type-only positive controls still require exit zero.

All 36 lint checks generated by `gate-checks.ts`, `gate-lint-checks.ts`,
`gate-runtime-checks.ts` and `gate-scope-checks.ts` use the shared verifier call.
These include both complexity measures, restricted types/imports, file length,
type-aware promises, disable directives, edge files, testing imports and artifact
exclusion. No other command family receives the formatter argument.

## Evidence and limits

- Shard 11/16 passed completely under the GitHub-reporting environment above,
  including its full-suite positive coverage control.
- Shard 12/16 passed SDK rejection for `.tsx`, then failed the unrelated
  `artifacts excluded from test (ts)` positive control: 612/615 source tests passed;
  standalone-bin tests had two unchanged 5-second timeouts and `spawnSync bun
ENOENT`. This is not a full shard-12 or aggregate-green claim.
- Direct public `bun run lint <fixture>` controls confirmed that ordinary
  GitHub annotations still identify the SDK restriction, return exactly exit 1
  for both runtime imports, and accept both type-only imports with exit zero.
- The production SDK restriction and `.ts`/`.tsx` negative fixtures remain intact.
  No thresholds, watchdogs or tighter test/hook limits were changed, and no
  mutation testing was introduced.

Scratch evidence is under the approved OpenCode temporary directory:
`verification-lint-reporting-red.log`, `verification-lint-reporting-green-11.log`
and `verification-lint-reporting-green-12.log`; the direct production controls
are in `verification-lint-reporting-production.log`.
